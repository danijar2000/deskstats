# Как устроен deskstats

Справка для тех, кто хочет разобраться в коде или написать свой клиент. Для установки и
работы она не нужна — см. [README](../README.md).

## Состав

- `server/` — сервер для Mac на Rust (1.82 и новее), без сторонних библиотек: всё через
  системные библиотеки macOS. Модули: `main` (параметры и цикл замеров), `sampler` (процессор,
  память, сеть, видеоядро, батареи), `procs` (нагрузка по приложениям), `alerts` (уведомления),
  `weather` (погода с open-meteo.com), `http` (сервер для телефона), `crypto` (шифрование),
  `lan` (маяк в Wi-Fi), `power` (сон и выключение Mac), `adb` (связь по USB), `util`.
- `android/` — приложение на Kotlin без библиотек, всё нарисовано на Canvas, Android 2.3+.
- `server/install.sh` собирает сервер (или берёт готовый из релиза), упаковывает его в
  `~/Applications/Deskstats.app`, подписывает и регистрирует агент launchd
  `app.deskstats.server`.
- `setup.sh` скачивает готовые сборки из GitHub Releases и вызывает `install.sh`.
- `.github/workflows/build.yml` на каждый push проверяет и собирает сервер (Apple silicon и
  Intel в одном файле) и APK; на тег `v*` публикует релиз.

## Связь телефона и Mac

По USB телефон обращается к `127.0.0.1:8787` у себя, а `adb reverse`, который сервер настраивает
сам, переносит соединение на Mac. С `--lan` сервер отвечает ещё и в Wi-Fi и каждые 3 секунды
рассылает маяк `DESKSTATS2 <ip> <port> <время> <hmac>` на UDP-порт 8788. Телефон принимает
маяк только с подписью своим токеном, с того адреса, который в нём назван, только частный адрес
(10.x, 172.16–31.x, 192.168.x) и только новее прошлого.

### Токен

Создаётся при первом запуске в `~/Library/Application Support/deskstats/token` (права 0600).
В запросах он не передаётся: обе стороны выводят из него два ключа и шифруют всё, что говорят
друг другу. Когда телефон появляется на USB, сервер передаёт ему порт и токен через
`adb shell` (на вход команды, не аргументом):

```
am start -n app.deskstats/.ConfigActivity --ei port 8787 --es token <токен>
```

`ConfigActivity` может запустить только оболочка adb (нужно право `DUMP`), поэтому другие
приложения на телефоне не могут подменить сервер. На Android до 4.1 это право мог получить
кто угодно, поэтому там сохранённый токен не заменяется — чтобы связать заново, очистите данные
приложения. На Android до 7 другие приложения могут увидеть токен в командной строке, пока
работает `am`.

Любая программа, запущенная от имени владельца Mac, может прочитать файл токена, а с ним и
уведомления. Хранение в связке ключей это закрыло бы, но требовало бы подтверждения после каждой
пересборки, поэтому не сделано. Сменить токен: удалить файл и перезапустить сервер — телефон
получит новый по USB.

### Запросы

Телефон спрашивает `GET /q?<hex>` — одинаково по USB и Wi-Fi. `hex` — запечатанный текст
`Q\n<nonce>\n<цель>`: IV (16 байт) | шифртекст AES-256-CBC | HMAC-SHA256 (32 байта) от обоих.
Ключи — `HMAC(токен, "deskstats-enc")` и `HMAC(токен, "deskstats-mac")`. `nonce` — от 16 до 64
букв и цифр, выбирает телефон. Цели:

```
/stats                       каждый опрос
/stats?place=<широта>,<долгота>  погода этого места вместо города из --city
/stats?alerts=full           до 30 уведомлений вместо 6 последних
/procs?sort=cpu|ram|net|gpu  16 самых тяжёлых приложений по этой мере
```

Ответ — `200` с телом `application/octet-stream`, запечатанным так же:
`A\n<nonce>\n<статус>\n<json>`, дополненный пробелами до кратного 1024 байтам. Телефон
принимает ответ только со своим `nonce`, так что старый ответ не подсунуть. Статус внутри:
`200`, `503` (сервер запускается или выходит из паузы — без опросов он не замеряет) или `404`.

Запрос, не запечатанный токеном, получает `401` и ничего не запускает; соединение закрывается.
Так же закрывается соединение, которое за 3 секунды не прислало ни одного верного запроса.

Вручную, только на самом Mac, те же цели отдаются открытым JSON:

```bash
curl -H "Authorization: Bearer $(cat ~/Library/Application\ Support/deskstats/token)" 'http://127.0.0.1:8787/procs?sort=ram'
```

Коды там: `200`, `503`, `404`; `401` — нет или неверный токен, а также любой открытый запрос из
сети; `421` — неожиданный `Host` (защита от DNS rebinding); `403` — запрос с `Origin`
(браузеры); `405`; `400` (в том числе запрос с телом); `431`. Запечатанный запрос получает
`500`, если ответ не удалось зашифровать. Тело ошибки — `{"error":"…"}`.

`/procs` стоит ресурсов (запускает `ps` и `nettop`, читает клиентов видеоядра), поэтому сервер
делает это только по запросу, а телефон спрашивает только пока открыта страница приложений;
через 10 секунд после последнего запроса всё собранное для неё выбрасывается. Процессы
группируются по пакету приложения. Неизвестный `sort` считается `cpu`. Место для погоды
запрашивается сразу, затем раз в `--weather-hours`; хранится не больше четырёх мест, место,
которое больше не спрашивают, забывается; нечитаемый `place` получает `"weather": null`.

### JSON

`/stats`:

```
ts, interval_ms, mac            часы Mac (мс), период замеров, awake | display_off | sleep
cpu {name, pct}                 gpu {pct, mem_used} | null
ram {used, total, pct}          net {down_bps, up_bps}
batteries [{kind, name, pct}]   weather {city, temp, feels, code, is_day, max, min} | null
alerts [{id, ts, app, title, subtitle, body}]   нет поля: выключены; null: не читаются
```

`/procs`:

```
sort                            по какой мере отсортировано
total                           сколько приложений всего
procs [{name, cpu, ram, down, up, gpu, count}]   cpu — в % одного ядра, gpu — в % видеоядра
```

Пока Mac засыпает, оба отвечают просто `{"mac":"sleep"}`.

Единицы: байты, байты в секунду, миллисекунды с начала эпохи, °C, коды погоды WMO.

### Сон

`mac` в ответе — `awake`, `display_off` (экран погас, крышка закрыта) или `sleep` (Mac
засыпает, выключается или выходит пользователь — сервер держит это до 3 секунд, чтобы
опрашивающий телефон успел увидеть; при `--interval` больше 3 секунд при выключении телефон
может этого не застать). Панель тогда гаснет — на AMOLED чёрные пиксели не светятся — и
загорается, как только Mac снова ответит `awake`.

## Журналы

`~/Library/Logs/deskstats.log`. При запуске, если он больше 1 МБ, от него остаётся последняя
четверть. `--ax-dump` пишет дерево окна Центра уведомлений (с текстами уведомлений) в
`~/Library/Logs/deskstats-ax.log` — только для владельца, не больше 2 МБ, заново при каждом
запуске. Нужно, чтобы подстроить разбор окна под новую версию macOS.

## Сборка из исходников

Сервер: нужен Rust (`brew install rust`).

```bash
(cd server && cargo test)
(cd server && ./install.sh --interval 1 --city Bishkek --lan)
```

Приложение: нужен JDK 17 или новее (`brew install openjdk@21`) и Android SDK с платформой 34;
SDK ищется через `ANDROID_HOME` или `sdk.dir=…` в `android/local.properties`. Версия Gradle
закреплена в wrapper вместе с контрольной суммой; плагины Android, которые он скачивает, по
контрольным суммам не проверяются.

```bash
(cd android && ./gradlew :app:assembleRelease)
adb install -r android/app/build/outputs/apk/release/app-release.apk
```

Релизная сборка подписана отладочным ключом той машины, где собрана: APK с другого компьютера
или из GitHub Actions не встанет поверх без удаления приложения.

Подпись сервера: без сертификата macOS привязывает разрешения к конкретному файлу, и после
каждой пересборки их надо выдавать заново. С сертификатом из связки ключей
(`security find-identity -v -p codesigning`) они сохраняются:

```bash
(cd server && DESKSTATS_SIGN_IDENTITY="<имя или хеш>" ./install.sh --interval 1 --city Bishkek --lan)
```

Но тогда разрешения привязаны к ключу, и их получит любая программа, подписанная им: держите
сертификат в запертой связке и не разрешайте `codesign` пользоваться им без спроса.
